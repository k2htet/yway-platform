# Documentation Instructions

These instructions apply under `docs/` in addition to repository-wide rules.

- Apply the authority rules in root `AGENTS.md`. Identify the document type and its closest local
  instructions before editing.
- Read only the source sections needed for the proposed statement. Prefer links and exact IDs over
  copying large canonical passages into lower-authority documents.
- When documentation exposes an unresolved product or architecture question, record it as a
  follow-up instead of expanding the current edit.
- Keep documentation-only work within `docs/` and instruction files unless a required validation
  check identifies a concrete issue elsewhere.
- When a matching ExecPlan is already identified or the task requires one, follow its applicable
  checks. Do not search ExecPlans for trivial documentation work. Formatting and structural checks
  do not validate product meaning.
